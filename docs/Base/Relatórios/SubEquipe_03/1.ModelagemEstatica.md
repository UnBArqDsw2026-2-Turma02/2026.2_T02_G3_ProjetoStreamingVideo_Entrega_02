## Metodologia do Foco_01

### Metodologia de Desenvolvimento do Diagrama de Classes

A elaboração do diagrama de classes para o sistema de *Video on Demand* (VOD) foi conduzida de forma colaborativa pelos integrantes da subequipe,
utilizando uma metodologia estruturada em reuniões de alinhamento técnico, análise iterativa de domínio e aplicação dos padrões formais da [**Unified Modeling Language (UML)**](#ref1), integrando conceitos formais de modelagem orientada a objetos [LES/PUC-Rio](#ref5). Como insumo principal para a definição dos requisitos arquiteturais, rotas de interface e mapeamento do domínio de streaming, foi utilizado os relatórios e achados das pesquisas de engenharia reversa desenvolvidas tanto pela nossa equipe quanto pela [SubEquipe 02](#ref2), fundamentadas no estudo detalhado da plataforma PeerTube.

A partir das estruturas, serviços e fluxos mapeados na engenharia reversa, fez-se uso de Inteligência [Artificial Generativa](#ref6) para elaborar as primeiras versões e rascunhos do diagrama de classes. O uso da IA acelerou a prototipagem inicial e a identificação preliminar das entidades do sistema. Em seguida, o grupo realizou sessões iterativas de revisão técnica e refinamento manual sobre os esboços gerados por IA, ajustando visibilidades, validando associações e adequando o modelo às boas práticas formais da [especificação UML](#ref3) utilizando como ferramenta de diagramação um template de [Ken Ritley no Miro](#ref4).

O processo de refinamento e estruturação seguiu etapas bem definidas de análise e modelagem orientada a objetos [DevMedia](#ref1):

1. **Abstração e Delimitação do Escopo**: Aplicou-se o princípio da abstração para focar nos aspectos essenciais do domínio VOD, considerando também elementos relevantes e objetos tangíveis indispensáveis à aplicação do diagrama sobre a proposta do projeto [UML Class Diagrams](#ref3).

2. **Agrupamento e Eliminação de Redundâncias**: Para evitar duplicidades conceituais e a criação desnecessária de tabelas no banco de dados, os objetos foram agrupados por características semelhantes. Em seguida, eliminaram-se redundâncias, consolidando as classes fundamentais: `Usuario`, `Canal`, `Video`, `Playlist`... [DevMedia](#ref1).

3. **Definição da Estrutura Interna e Visibilidade**: As classes foram formalizadas na notação UML em retângulos divididos em três seções (Nome, Atributos e Métodos). Adotou-se o padrão de nomenclatura no singular com inicial maiúscula [LES/PUC-Rio](#ref5), especificando os níveis formais de visibilidade: público (`+`), protegido (`#`) e privado (`-`) [DevMedia](#ref1)[LES/PUC-Rio](#ref5).

Foi realizada um gravação onde comentamos um pouco sobre evolução da diagramação e proximos passos que pode ser conferida nessa [ata-16-09](./../../../assets/SubGrupo03/atas/16-09.md) e a final em [ata-17-09](.//../../../assets/SubGrupo03/atas/17-09.md)

## Modelo Estático - Diagrama de Classe

A escolha do subgrupo pelo diagrama de classes ocorreu devido a sua estruturação e legibilidade, facilitando uma futura codificação do que está no diagrama. Esse diagrama permite representar de forma clara as principais classes do sistema, seus atributos, métodos e relacionamentos. Dessa forma, sua elaboração contribui para compreender e organizar a estrutura do sistema de VOD, facilitando a visualização de como seus diferentes elementos se relacionam.

#### Detalhamento

#### Nomenclatura e Convenções UML

* **Classes**: Substantivos no singular com inicial maiúscula (`Usuario`, `Video`, `Canal`).
* **Visibilidade**: Privado (`-`) para todos os atributos, garantindo o encapsulamento; Público (`+`) para métodos expostos.
* **Métodos**: Verbos no infinitivo especificando o tipo de retorno (ex: `cadastrar() : Boolean`, `atualizarProgresso() : void`).
* **Restrições e Padrões**: Especificação explícita de restrições `{único}`, `{não nulo}` e valores *default* (ex: `totalVisualizacoes : Integer = 0`).

---

#### Detalhamento das Classes

* **Instancia**: Representa o nó/servidor federado que hospeda as contas e vídeos.
  * **Atributos**: `- id : Integer {único}`, `- dominio : String {único, não nulo}`, `- nome : String {não nulo}`, `- cotaArmazenamentoBytes : Long = 5368709120`.
  * **Métodos**: `+ configurarInstancia() : Boolean`, `+ sincronizarFederacao() : void`.
* **Usuario**: Gerencia a autenticação e dados cadastrais da conta local.
  * **Atributos**: `- id : Integer {único}`, `- nomeUsuario : String {único, não nulo}`, `- email : String {único, não nulo}`, `- senhaHash : String {não nulo}`, `- dataCadastro : Date`.
  * **Métodos**: `+ cadastrar() : Boolean`, `+ autenticar() : Boolean`, `+ editarPerfil() : void`.
* **Canal**: Agrupador público sob o qual os vídeos são publicados.
  * **Atributos**: `- id : Integer {único}`, `- nomeCanal : String {único, não nulo}`, `- descricao : String`, `- totalInscritos : Integer = 0`, `- dataCriacao : Date`.
  * **Métodos**: `+ criarCanal() : Boolean`, `+ atualizarInformacoes() : void`, `+ obterEstatisticas() : String`.
* **Video**: Entidade central do sistema VOD, armazenando os metadados do conteúdo gravado.
  * **Atributos**: `- id : Integer {único}`, `- uuid : String {único, não nulo}`, `- titulo : String {não nulo}`, `- descricao : String`, `- duracaoSegundos : Integer = 0 {duracao &gt; 0}`, `- totalVisualizacoes : Integer = 0`, `- dataPublicacao : Date`, `- urlTorrent : String`, `- permiteComentarios : Boolean = true`.
  * **Métodos**: `+ publicar() : Boolean`, `+ incrementarVisualizacao() : void`, `+ obterUrlPublica() : String`, `+ iniciarProcessamento() : void`, `+ solicitarTranscodificacao() : void`.
* **ArquivoVideo**: Arquivo físico de mídia renderizado em determinada resolução ou formato de transmissão (ex: HLS).
  * **Atributos**: `- id : Integer {único}`, `- resolucao : String {não nulo}`, `- tamanhoBytes : Long = 0`, `- fps : Integer = 30`, `- urlArquivo : String {não nulo}`, `- ehHLS : Boolean = true`.
  * **Métodos**: `+ obterUrlDownload() : String`, `+ validarIntegridade() : Boolean`.
* **JobTranscodificacao**: Registra tarefas assíncronas de conversão do vídeo no servidor.
  * **Atributos**: `- id : Integer {único}`, `- estadoJob : String = "PENDENTE"`, `- tipoFormatacao : String`, `- dataInicio : Date`.
  * **Métodos**: `+ iniciarJob() : void`, `+ concluirJob() : void`, `+ registrarFalha() : void`.
* **Playlist**: Coleção de vídeos organizados criada pelos usuários.
  * **Atributos**: `- id : Integer {único}`, `- titulo : String {não nulo}`, `- ehPublica : Boolean = true`, `- dataCriacao : Date`.
  * **Métodos**: `+ adicionarVideo() : Boolean`, `+ removerVideo() : Boolean`.
* **ItemPlaylist**: Elemento de ligação que define a ordem de um vídeo em uma playlist.
  * **Atributos**: `- posicao : Integer`, `- dataAdicao : Date`.
  * **Métodos**: `+ reordenar() : void`.
* **Comentario**: Mensagens enviadas pelos usuários na página do vídeo.
  * **Atributos**: `- id : Integer {único}`, `- texto : String {não nulo}`, `- dataCriacao : Date`, `- totalCurtidas : Integer = 0`.
  * **Métodos**: `+ publicarComentario() : Boolean`, `+ excluirComentario() : Boolean`.
* **HistoricoDeVisualizacao**: Registra o progresso de reprodução individual para retomada de exibição no VOD.
  * **Atributos**: `- id : Integer {único}`, `- tempoParadaSegundos : Integer = 0`, `- dataUltimoAcesso : Date`.
  * **Métodos**: `+ atualizarProgresso() : void`, `+ limparHistorico() : void`.
* **Inscricao**: Guarda a relação de acompanhamento de canais pelo usuário.
  * **Atributos**: `- dataInscricao : Date`, `- receberNotificacoes : Boolean = true`.
  * **Métodos**: `+ alternarNotificacoes() : void`.

#### Detalhamento dos Relacionamentos

1. **Instancia** **1** **\*--** **0..\*** **Usuario** **(Composição)**: Uma instância hospeda zero ou vários usuários. Se a instância deixa de existir, suas contas locais são destruídas.
2. **Usuario** **1** **\*--** **0..\*** **Canal** **(Composição)**: Um usuário possui a propriedade de zero ou mais canais.
3. **Canal** **1** **o--** **0..\*** **Video** **(Agregação)**: O canal atua como agrupador para a publicação de vídeos VOD.
4. **Video** **1** **\*--** **1..\*** **ArquivoVideo** **(Composição)**: Cada vídeo compõe-se de pelo menos uma resolução/arquivo físico gerado.
5. **Video** **1** **\*--** **0..\*** **JobTranscodificacao** **(Composição)**: O vídeo controla o ciclo de vida dos seus jobs de processamento.
6. **Usuario** **1** **\*--** **0..\*** **Playlist** **(Composição)**: O usuário é proprietário direto das playlists por ele criadas.
7. **Playlist** **1** **\*--** **0..\*** **ItemPlaylist** **(Composição) e** **ItemPlaylist** **0..\*** **\--&gt;** **1** **Video** **(Navegabilidade)**: A playlist compõe itens que referenciam o vídeo correspondente na ordem da lista.
8. **Usuario** **1** **\--&gt;** **0..\*** **Comentario** **e** **Video** **1** **\*--** **0..\*** **Comentario**: O usuário escreve comentários; cada vídeo armazena e exibe os comentários recebidos.
9. **Usuario** **1** **\*--** **0..\*** **HistoricoDeVisualizacao** **e** **HistoricoDeVisualizacao** **0..\*** **\--&gt;** **1** **Video**: O usuário mantém um histórico de acessos que registra o tempo exato de parada para cada vídeo VOD.
10. **Usuario** **1** **\*--** **0..\*** **Inscricao** **e** **Inscricao** **0..\*** **\--&gt;** **1** **Canal**: Associa o usuário ao canal que ele acompanha, registrando preferências de notificação.

### Diagrama de Classe V0.1

Nessa primeira versão, podemos observar que o diagrama de classe ainda não está suficientemente elaborado e apresenta algumas inconsistências em relação às notações e aos princípios da UML. Embora a estrutura faça sentido quando analisamos isoladamente os elementos identificados durante a pesquisa sobre o PeerTube, ela ainda não representa de forma adequada um diagrama de classes completo. É necessário aprimorar a identificação e a organização das classes, seus atributos, métodos e relacionamentos, de modo que o diagrama esteja mais alinhado aos requisitos levantados.
